# Agent：两条线合流 + 状态 + 摘要记忆

## 架构总览

```
Agent 演进流程（t01 → t03，每个文件在上一个基础上加一件事）：

  t01 两条线合流：RAG as a Tool
  ─────────────────────────────────────────────
  RAG 线的向量检索封装成 search_knowledge 工具
       │
       ▼
   注册进 Tool Calling 线的 Agent Loop
       │
       ▼
   LLM 自己判断：需要知识库时才调 search_knowledge，
   闲聊/算术直接回答不查库
       │
       ▼
   检索结果就是 Prompt，LLM 严格按内容回答、查不到就说没查到

  t02 有状态的 Agent
  ─────────────────────────────────────────────
  AgentState（dataclass）外置
       │  main() 创建长期持有，agent() 只使用不创建
       ▼
   对话历史跨轮保留 → 多轮对话
       │
       ▼
   工具表合并：三个计算函数 + search_knowledge
       │
       ▼
   MAX_STEPS 限制单次任务步数，防止无限循环

  t03 摘要记忆：突破上下文上限
  ─────────────────────────────────────────────
  消息数超过阈值
       │
       ▼
   旧消息交给 LLM 总结成摘要（带着旧摘要滚动叠加）
       │
       ▼
   历史里只留 system + 摘要 + 最近几条消息
       │
       ▼
   每轮由 build_context 现场组装上下文发给 LLM
```

## 文件清单

| 文件 | 角色 | 关键点 |
|---|---|---|
| `t01_rag_agent.py` | 合流 | search_knowledge 注册成工具，检索时机交给 LLM 决定 |
| `t02_agent.py` | 有状态的 Agent | AgentState 外置 + 多轮对话 + MAX_STEPS，刻意回退了校验/超时 |
| `t03_summary_memory.py` | 摘要记忆 | 滚动摘要压缩历史；切分必须落在 user 消息边界 |

## 一条主线

工具从"计算器"扩展到"知识库"，状态从"函数参数"升级为"长期持有的 state"，记忆从"全部塞进上下文"进化到"摘要 + 最近消息"。每个文件只聚焦一个新概念，t02 是刻意简化的框架骨架。
